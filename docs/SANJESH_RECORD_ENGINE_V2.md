# قرارداد موتور گزینش سوابق تحصیلی سنجش — V2

این سند قرارداد مسیر `admission_path=record` است و فقط به داده و منطق پذیرش مربوط می‌شود. این مسیر از موتور فردیت، scoring/ranking فردیت، Hybrid و cutover مستقل است.

## 1) ورودی‌های مجاز record

ورودی معتبر مسیر سوابق شامل این موارد است:

- `diploma_type`
- `gpa_written` یا `gpa_total` مطابق نوع دیپلم
- `province` به‌صورت استان معتبر
- `region_zone` فقط در مواردی که قرارداد/دفترچه برای آن مسیر اثر عملی دارد
- `special_quota`: بدون سهمیه، ایثارگران ۲۵٪، ایثارگران ۵٪، یا شهدا
- `major_ids`
- `rank` / `rank_in_quota` جزء ورودی لازم مسیر record نیست و برای مقایسه cutoff سوابق استفاده نمی‌شود.

## 2) قواعد تعیین bomi_type

ترتیب حل نوع بومی باید deterministic و بدون حدس باشد:

### الف) پیش‌فرض دوره از جدول ۵

منبع: `docs/sanjesh_table5_major_bomi_v1.json`، بخش `period_defaults`.

قاعده‌های ثبت‌شده برای این نسخه:

- `payam_noor` / `payam` → `nahiyei`
- `non_profit` / `nonprofit` / `gheyre_entefai` → `nahiyei`
- `nobat2` / `nobat_dovom` / `shabane` → `ostani`
- `virtual` / `majazi` → `keshvari`
- `pardis` → `keshvari`
- `mazad` و دوره‌های مشترک ثبت‌شده در `period_defaults` → `keshvari`، فقط در صورت انطباق با نام دورهٔ داده.

### ب) روزانه دولتی سوابق (`savabegh_dolati`)

برای این مسیر، نوع بومی نباید از حدس دوره استخراج شود.

1. `major_id` باید به نام رشته از منبع رسمی ریپو یعنی `majors_database_v2.json` نگاشت شود.
2. سپس نام رشته با `daily_major_bomi` در جدول ۵ تطبیق داده می‌شود.
3. تطبیق با `name_aliases` جدول ۵ نیز مجاز است.
4. اگر `major_id` یا نام رشته قابل resolve نباشد، نتیجهٔ نوع بومی `null` و rule برابر `unresolved_table5` است؛ حدس جغرافیایی ممنوع.

### ج) آزاد (Azad)

تا وقتی منبع رسمی و کافی برای سیاست بومی‌گزینی آزاد در داده پروژه وجود نداشته باشد:

- نباید `ghotbi` یا `nahiyei` اختراع شود.
- خروجی باید note شفاف مانند «سامانه آزاد؛ بومی‌گزینی سراسری کامل نیست» داشته باشد، یا از یک سیاست موقت صریحاً مستند در قرارداد استفاده کند.

### د) عدم تطبیق

هر program که نوع بومی آن از منبع قابل resolve نباشد:

- `bomi_type=null`
- rule و note شفاف
- بدون استنتاج قطب/ناحیه/استان

## 3) فیلتر جغرافیا

منبع جغرافیا فقط:

`docs/bomi_geography_v1.json`

است.

قاعده‌ها:

- `ostani` → استان داوطلب دقیقاً برابر `university.province`
- `nahiyei` → `nahiye_id` استان داوطلب و دانشگاه یکسان
- `ghotbi` → `ghotb_id` استان داوطلب و دانشگاه یکسان
- `keshvari` → بدون فیلتر جغرافیایی
- `null` → ترجیحاً در نتایج اصلی وارد نشود؛ در صورت نگه‌داری فقط با note صریح «بومی نامشخص»

اگر geography ناقص باشد، هیچ `nahiye_id` یا `ghotb_id` جدیدی حدس زده نمی‌شود.

## 4) cutoff مسیر سوابق

فقط دادهٔ زیر مجاز است:

`program.cutoffs_savabegh`

و فقط فیلدهای موجود مانند:

- `minimum_gpa`
- `minimum_traz`

مجاز هستند.

قواعد:

- مقایسهٔ rank با cutoff در مسیر record ممنوع.
- `cutoffs_bomi` cutoff رسمی سنجش محسوب نمی‌شود.
- نبود cutoff نباید با دادهٔ دیگری به‌صورت silent fallback جبران شود.

## 4.1) G2 — آستانه معدل و تراز در مسیر record

این قاعده ثابت است و قبل از هرگونه کالیبراسیون یا عدد شانس اجرا می‌شود.

- ورودی معدل بر اساس نوع دیپلم تعیین می‌شود: برای دیپلم نظری gpa_written و برای دیپلم فنی/کاردانش gpa_total.
- اگر program.cutoffs_savabegh.minimum_gpa وجود داشته باشد و معدل ورودی کاربر کمتر از آن باشد، program از نتایج حذف می‌شود؛ صرفاً به label پایین‌تر تبدیل نمی‌شود.
- minimum_gpa با خود معدل ورودی مقایسه می‌شود، نه با gpa_effective. ضریب اثر معدل در G3 جداگانه بررسی می‌شود و نباید آستانه G2 را تغییر دهد.
- اگر program.cutoffs_savabegh.minimum_traz وجود داشته باشد و کاربر traz ارسال نکرده باشد، فیلتر تراز اعمال نمی‌شود و note می‌تواند «تراز اعلام نشده؛ فیلتر حداقل تراز برای این برنامه اعمال نشد.» باشد.
- اگر traz ارسال شود و کمتر از minimum_traz باشد، program از نتایج حذف می‌شود.
- برابر بودن معدل یا تراز با حداقل، program را حذف نمی‌کند.
- rank / rank_in_quota در مسیر record برای cutoff استفاده نمی‌شود و همچنان ممنوع است.
- اگر minimum_gpa یا minimum_traz در program موجود نباشد، هیچ fallback یا مقدار حدسی ایجاد نمی‌شود.

## 4.2) G3 — ضریب اعمال معدل در پذیرش صرفاً بر اساس سوابق تحصیلی

منبع: دفترچه/ویژه‌نامه رسمی پذیرش صرفاً بر اساس سوابق تحصیلی سراسری ۱۴۰۴، جدول «ضریب تأثیر اعمال سوابق تحصیلی» و footnote مربوط به رشته‌های علوم انسانی.

### جدول پایه

| نوع دیپلم | ریاضی | تجربی | انسانی | معارف | سایر |
|---|---:|---:|---:|---:|---:|
| ریاضی فیزیک | 100 | 100 | 57.1 | 57.1 | 51.4 |
| علوم تجربی | 100 | 100 | 57.1 | 57.1 | 51.4 |
| علوم انسانی | 57.1 | 57.1 | 100 | 100 | 51.4 |
| هنر | 100 | 100 | 100 | 100 | 100 |
| زبان | 100 | 100 | 100 | 100 | 100 |

مقادیر 100، 57.1 و 51.4 عین ضرایب جدول منبع هستند؛ تبدیل یا کالیبراسیون دیگری روی آنها انجام نمی‌شود.

### استثنای رسمی علوم انسانی

برای متقاضی دارای دیپلم ریاضی فیزیک یا علوم تجربی، footnote دفترچه ۱۴۰۴ ضریب 100 را برای رشته‌های اعلام‌شده‌ای مانند حسابداری، اقتصاد، روان‌شناسی و مجموعه مشخصی از مدیریت‌ها تعیین می‌کند.

در این نسخه فقط نام‌هایی که با نام موجود در `majors_database_v2.json` انطباق قطعی دارند override می‌شوند:

- روانشناسی
- اقتصاد
- مدیریت بازرگانی
- مدیریت صنعتی
- مدیریت مالی
- مدیریت بیمه
- مدیریت دولتی
- مدیریت امور بانکی
- حسابداری

برای نام‌هایی از footnote که در داده فعلی رشته متناظر قطعی ندارند، نگاشت یا alias حدسی انجام نمی‌شود.

### API و محاسبه

- API مسیر `record` فیلد `gpa_coefficient` را برمی‌گرداند.
- در صورت وجود ضریب رسمی، `gpa_effective = gpa_input × gpa_coefficient / 100` محاسبه می‌شود.
- `gpa_input` همچنان مطابق G2 از `gpa_written` برای دیپلم نظری و `gpa_total` برای فنی/کاردانش می‌آید.
- استثنا فقط ضریب را تغییر می‌دهد؛ سیاست G2 برای `minimum_gpa` و `minimum_traz` تغییر نمی‌کند.
- اگر ترکیب دیپلم × گروه هدف در جدول پایه موجود نباشد، مقدار جعلی تولید نمی‌شود و note شفاف برگردانده می‌شود.

### فرانت

مسیر record ضریب معدل و معدل مؤثر برگشتی از API را در کارت نتیجه نمایش می‌دهد. این نمایش مستقل از scoring/ranking فردیت است.

## 5) خروجی

خروجی مسیر record باید:

- فقط label کیفی ارائه کند.
- `bomi_type` مورد استفاده را در صورت resolve شدن اعلام کند.
- `notes[]` را برای محدودیت داده، بومی ناقص، آزاد، unresolved و سایر قیود نگه دارد.
- در صورت وجود cutoff سوابق، آن را از `cutoffs_savabegh` گزارش کند.
- شامل disclaimer روشن باشد که خروجی جایگزین دفترچه و اعلام رسمی سازمان سنجش نیست.
- هیچ درصد عددی شانس، احتمال یا ادعای دقت عددی تولید نکند.

## 6) کنترل دامنه

این قرارداد:

- هیچ تغییری در `dark_horse_engine`، JSONهای علمی فردیت، scoring یا ranking فردیت ایجاد نمی‌کند.
- Hybrid و PostgreSQL runtime cutover را فعال یا تغییر نمی‌دهد.
- ظرفیت تفکیکی رسمی را از خود ابداع نمی‌کند.
- مرحلهٔ کالیبراسیون چندساله و هر درصد عددی شانس خارج از این موج است.
