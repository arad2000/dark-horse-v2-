# پروتکل DH-013 (نسخه نهایی بازبینی‌شده)

**Dark Horse Cognitive Fulfillment Mapping — Version 13.0**

> این فایل تبدیل Markdown از سند مرجع ناظر «پروتکل ۱۳.docx» است. ترتیب، اصول، مراحل، آستانه‌ها و نمونه‌های پروتکل مرجع حفظ شده‌اند؛ این تغییر صرفاً مستندات است و schema، موتور یا داده‌های محصول را تغییر نمی‌دهد.

## مقدمه

پروتکل DH-013، نسخهٔ نهایی و بازبینی‌شدهٔ فرآیند نگاشت شناختی رشته‌های تحصیلی بر اساس کتاب «اسب سیاه» است. این پروتکل حاصل اجرای چندین دور بازخورد، اعتبارسنجی و اصلاح ساختاری روی نسخه‌های قبلی (DH-011 و DH-012) است و به‌عنوان استاندارد طلایی برای تولید دیتابیس `majors_database_v2.json` به کار می‌رود.

هدف پروژه ساخت موتور هدایت تحصیلی بر اساس «فردیت» است. این موتور رشتهٔ مناسب را انتخاب نمی‌کند، بلکه تجربه‌هایی را پیدا می‌کند که بیشترین احتمال «رضایت عمیق (Fulfillment)» را برای فرد ایجاد می‌کنند.

## بخش اول: چهار اصل بنیادین (غیرقابل تغییر)

1. **فردیت (Individuality):** موضوع پروژه «تجربهٔ شناختی رشته‌ها» است، نه «شخصیت افراد». هیچ خروجی نباید شخصیت افراد را توصیف کند. تمام خروجی‌ها فقط تجربهٔ روزانهٔ رشته را توصیف می‌کنند.
2. **Micro Motives:** تنها دادهٔ مجاز `micro_motives.json` است. هر بخش باید توسط حداقل دو Micro Motive پشتیبانی شود. برای هر وزن اختصاصی (`motive_weights`)، هر گزینهٔ Strategy و هر قطب Value، باید دست‌کم ۲ کد Micro Motive به‌عنوان شاهد ثبت شود.
3. **Personal Strategies:** راهبردها ویژگی رشته نیستند؛ بلکه میزان همخوانی آن رشته با انواع راهبردها هستند. تمام Strategyها باید با این جمله بازنویسی شوند: «این رشته بیشترین همخوانی را با افرادی دارد که از این راهبرد استفاده می‌کنند.» نه «افراد این رشته چنین هستند.»
4. **Fulfillment:** برای هر رشته یک منبع رضایت عمیق (Fulfillment Source) تعریف شود. این منبع باید یک رویداد شناختی عینی باشد، نه یک عبارت کلیشه‌ای.

## بخش دوم: مراحل دوازده‌گانه (ضوابط اجرایی)

### مرحله ۱: استخراج شواهد (Evidence Extraction)

مطالعه و درک عمیق Micro Motiveهای مرتبط با رشته.

### مرحله ۲: امضای لذت محوری (Core Enjoyment Signature)

- خروجی: یک جمله (DNA رشته).
- مثال پزشکی: «لحظه‌ای که پازل علائم پراکنده به یک تشخیص منسجم تبدیل می‌شود و جان یک انسان نجات می‌یابد.»
- شرط: این جمله باید مستقیماً به حداقل ۳ Micro Motive ارجاع دهد.

### مرحله ۳: جملهٔ هویت (Identity Sentence)

- خروجی: یک پاراگراف کوتاه که زندگی روزانهٔ رشته را توصیف می‌کند.
- مثال پزشکی: «زندگی روزانهٔ پزشکی شامل شرح حال گرفتن، حل معماهای تشخیصی، تصمیم‌گیری در شرایط بحرانی و تحمل بار مسئولیت جان انسان‌هاست.»

### مرحله ۴: موتور شناختی (Cognitive Engine) + ماتریس ارجاع

خروجی باید هفت مؤلفه داشته باشد:

1. `core_verb`: فعل اصلی (مثلاً «تشخیص دادن»)
2. `operational_verb`: افعال عملیاتی (مثلاً «حل کردن پازل، تصمیم‌گیری سریع»)
3. `dominant_object`: شیء غالب (مثلاً «علائم پراکندهٔ بیماری»)
4. `dominant_reward`: پاداش غالب (مثلاً «نجات جان»)
5. `dominant_frustration`: ناامیدی غالب (مثلاً «ابهام تشخیصی»)
6. `time_horizon`: افق زمانی (مثلاً «کوتاه‌مدت تا بلندمدت»)
7. `interaction_mode`: نحوهٔ تعامل (مثلاً «مستقیم با انسان + تحلیل داده»)

برای هر مؤلفه، یک ماتریس ارجاع (Traceability Matrix) ثبت شود تا نشان دهد هر مؤلفه از کدام Micro Motiveها استخراج شده است.

### مرحله ۵: کهن‌الگوی شناختی (Cognitive Archetype)

- خروجی: یک برچسب واحد (مثلاً «تشخیصگر-نجاتبخش»).
- تعریف عملیاتی: برای هر Archetype، تعریف دقیقی بنویسید که مشخص کند با چه `Core Verb` و `Dominant Object` تعریف می‌شود. این کار از هم‌پوشانی Archetypeهای مشابه جلوگیری می‌کند.

### مرحله ۶: منبع رضایت عمیق (Fulfillment Source)

- خروجی: پاسخ به این سؤال: «این رشته چه زمانی برای یک انسان رضایت عمیق ایجاد می‌کند؟»
- مثال پزشکی: «وقتی علت واقعی بیماری کشف شود و بیمار بهبود یابد.»
- شرط: باید مستقیماً از `dominant_reward` و `dominant_frustration` استنتاج شود.

### مرحله ۷: ماتریس تمایز همسایگی (Neighbor Contrast Matrix)

- معیار انتخاب همسایه‌ها: نزدیک‌ترین رشته‌ها بر اساس اشتراک در `Core Verb` و اشتراک در `Dominant Object` انتخاب می‌شوند.
- خروجی: مقایسه با ۳ رشتهٔ نزدیک در ۶ بعد: Verb، Object، Reward، Frustration، Archetype و Fulfillment.
- مثال پزشکی: «پرستار پایش می‌کند، پزشک تشخیص می‌دهد.»

### مرحله ۸: اعتبارسنجی تمایز (Discrimination Validation)

- شرط: اگر نام رشته حذف شود، آیا از روی Identity Sentence، Archetype و Fulfillment Source می‌توان رشته را تشخیص داد؟
- اجرا: این تست باید توسط دست‌کم دو خبرهٔ مستقل انجام شود. اگر تشخیص ممکن نبود، مدل مردود است.

### مرحله ۹: تولید راهبردها (Strategy Generation)

- منبع استخراج: وزن‌های Strategy از `Operational Verb` و `Archetype` تولید می‌شوند.
- فرمت خروجی الزامی:

```json
{
  "strategy_profile": {
    "problem_approach": {
      "ساختارمحور": {
        "weight": 0.95,
        "evidence": ["MED-001", "MED-005"],
        "confidence": 0.90
      }
    }
  }
}
```

- قاعده: اگر `confidence < 0.7`، وزن باید با میانگین وزنی رشته‌های همسایه (مرحلهٔ ۷) تعدیل شود.

### مرحله ۱۰: تولید ارزش‌ها (Value Generation)

- منبع استخراج: Valueها از Reward، Frustration، Fulfillment، Interaction Mode و Time Horizon تولید می‌شوند.
- ماتریس تأثیر (Impact Matrix): برای هر یک از ۱۵ Value مشخص کنید هر مؤلفه چه سهمی (وزن نسبی) در تعیین آن Value دارد.
- فرمت خروجی الزامی:

```json
{
  "value_weights": {
    "Q1A": {
      "weight": 0.82,
      "evidence": ["MED-003", "MED-006"],
      "confidence": 0.85
    }
  }
}
```

### مرحله ۱۱: تست جداسازی جهانی (Global Separation Test)

**آستانهٔ پویا:**

- رشته‌های داخل یک خوشهٔ همگن (مثل تمام رشته‌های مهندسی): آستانهٔ تشابه = ۷۰٪.
- رشته‌های بین‌خوشه‌ای (مثل پزشکی و پرستاری): آستانهٔ تشابه = ۵۰٪.
- اگر بیش از ۶۰٪ از مقایسه‌های یک رشته با همسایگانش بالاتر از حد مجاز باشد، مدل برای آن رشته مردود اعلام می‌شود.

### مرحله ۱۲: تولید JSON نهایی

- فقط پس از تأیید تمام مراحل قبل، JSON تولید شود.
- ساختار الزامی فایل نهایی `majors_database_v2.json` در نمونهٔ مرجع:

## بخش سوم: چک‌لیست نهایی اعتبارسنجی (قبل از تأیید نهایی)

1. آیا `motive_weights` برای تمام کدهای `micro_motive_codes` تعریف شده است؟
2. آیا برای هر وزن در `strategy_profile` حداقل ۲ شاهد (`evidence`) ثبت شده است؟
3. آیا برای هر وزن در `value_weights` حداقل ۲ شاهد (`evidence`) ثبت شده است؟
4. آیا تمام `confidence`ها ≥ ۰.۷ هستند؟ در غیر این صورت، وزن با میانگین همسایگان تعدیل شود.
5. آیا `neighbor_contrast` بر اساس معیار عینی (`Core Verb` و `Object`) انتخاب شده است؟
6. آیا تست جداسازی (مرحلهٔ ۱۱) با آستانهٔ پویا برای این رشته موفق بوده است؟
7. آیا `Fulfillment Source` مستقیماً از Reward و Frustration قابل استنتاج است؟

## اصل نهایی پروژه

این پروژه مدل‌سازی «رشته‌ها» نیست؛ مدل‌سازی «تجربهٔ شناختی و رضایت عمیق ناشی از فعالیت‌های هر رشته» است.

تمام خروجی‌ها باید به این پرسش پاسخ دهند: «این رشته چه نوع تجربهٔ روزانه‌ای ایجاد می‌کند، چه نوع موتور شناختی را فعال می‌سازد، چه زمانی احساس رضایت عمیق (Fulfillment) به وجود می‌آورد و با کدام راهبردها و ارزش‌های فردی بیشترین همخوانی را دارد؟»

موفقیت پروژه زمانی است که دو رشتهٔ نزدیک، حتی اگر ابزار، دانش یا محیط مشابهی داشته باشند، از نظر هویت شناختی، منبع رضایت، شیوهٔ اندیشیدن و تجربهٔ روزانه به‌وضوح از یکدیگر قابل تمایز باشند و این تمایز مستقیماً از Micro Motiveها و فلسفهٔ چهارگانهٔ کتاب «اسب سیاه» قابل استنتاج باشد.
