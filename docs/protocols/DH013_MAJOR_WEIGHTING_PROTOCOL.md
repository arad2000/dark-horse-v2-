# پروتکل وزن‌دهی رشته‌ها — اسب سیاه (DH-013)

این سند، روش دقیقی‌ست که برای وزن‌دهی ۱۶۰ رشتهٔ اول دیتابیس (و اصلاح مکررشان) استفاده شد. هر قانونش از یک اشتباه واقعی که رخ داد و پیدا/اصلاح شد می‌آید — نه یک روش نظری. برای ~۵۰ رشتهٔ جدید باید **دقیقاً همین ترتیب** رعایت شود.

---

## اصل بنیادین

> **تنها دادهٔ مجاز برای وزن‌دهی، شواهد متنیِ میکرو-موتیوهای خودِ همان رشته است — نه اسم رشته، نه دانش عمومی دربارهٔ آن حرفه، نه الگوی رشته‌های «هم‌خانواده».**

دانش عمومی دربارهٔ یک حرفه، حتی وقتی معقول به‌نظر می‌رسد، می‌تواند ابعاد مهمی از آن رشته را که فقط در تجربهٔ روزمرهٔ واقعی‌اش (نه تصور بیرونی) قابل‌کشف است از قلم بیندازد. این دقیقاً چیزی‌ست که چندین‌بار در این پروژه رخ داد و باید دوباره اصلاح می‌شد.

## مرحلهٔ صفر — پیش‌نیاز برای هر رشته

قبل از نوشتن حتی یک عدد:

1. **۷ کد میکرو-موتیو** رشته را از `micro_motives.json` دربیاور و **متن کامل توضیح** هرکدام را بخوان (نه فقط کد).
2. متن **هر ۲۵ سؤال راهبردی** (`questions_v2.json` → `layers.strategies.questions`) و **۵ گزینهٔ هرکدام** را ببین.

⚠️ **نکتهٔ حیاتی**: شمارهٔ گزینه (۰ تا ۴) معنای ثابتی بین سؤالات مختلف ندارد. گزینهٔ ۰ در سؤال S01 ممکن است «تعریف دقیق مسئله» باشد ولی در سؤال دیگری چیز کاملاً متفاوتی. **هرگز فرض نکن که «گزینهٔ ۰ = تحلیلی» در همهٔ ۲۵ سؤال صادق است** — این دقیقاً خطایی بود که در اصلاحات اولیه رخ داد و باید جداگانه هر ۵ سؤال حیاتی (S01, S02, S04, S07, S25) تأیید می‌شد.

## مرحلهٔ ۱ — نگاشت شواهد به الگوی رفتاری

برای هر یک از ۷ جملهٔ شاهد، از خودت بپرس:

- این جمله چه سبک حل‌مسئله‌ای نشان می‌دهد؟ (دقیق/تحلیلی، آزمون‌وخطای عملی، شهودی، مشورتی؟)
- این رشته به تصمیم‌گیری **سریع زیر فشار** نیاز دارد یا **تأمل و بررسی کامل**؟
- کار **انفرادی و متمرکز** است یا **تیمی و مشورتی**؟
- پاداش اصلی‌اش **کمک مستقیم به دیگران**، **کشف/تحلیل حقیقت**، **تسلط فنی/زیبایی‌شناسی**، یا چیز دیگریست؟
- آیا شواهد نشان‌دهندهٔ **پایداری چندساله/پرمشقت** است (مثل اصلاح نژاد گیاهی، احیای آبخیز) یا کار کوتاه‌مدت؟

سپس برای هر یک از ۲۵ سؤال، گزینه‌ای را انتخاب کن که **متن دقیقش** با این الگو همخوانی دارد — نه گزینه‌ای که فقط شمارهٔ آشنایی دارد.

## مرحلهٔ ۲ — نوشتن وزن‌ها

هر سؤال یک ردیف ۵تایی‌ست که جمعش باید دقیقاً ۱ باشد. از این الگو استفاده کن:

```python
def to_row(d):
    total = sum(d.values()); row = [0.0]*5
    for idx, val in d.items(): row[idx] = round(val/total, 4)
    diff = round(1.0 - sum(row), 4)
    max_idx = max(d, key=d.get)
    row[max_idx] = round(row[max_idx] + diff, 4)
    return row

# مثال: برای یک سؤال با شواهد قوی تحلیلی + کمی سابقه‌محوری
row = to_row({0: 0.35, 4: 0.25, 3: 0.15, 2: 0.15, 1: 0.10})
```

### دو هشدار دربارهٔ *شکل* توزیع (نه فقط گزینهٔ برنده)

۱. **تنوع شکل بین رشته‌ها لازم است.** اگر همیشه از همان الگوی مغناطیسی (مثلاً ۰.۳۵/۰.۲۵/۰.۲۰/۰.۱۵/۰.۱۰) فقط با جابه‌جایی گزینهٔ برنده استفاده کنی، حتی با گزینهٔ‌برندهٔ متفاوت، شباهت آماری کل پروفایل‌ها بالا می‌ماند (این دقیقاً مشکلی بود که بعد از رفع تصادف‌های signature هنوز باقی مانده بود). جایی که شواهد قوی و یک‌دست‌اند، توزیع را تیزتر (مثلاً ۰.۴۰/۰.۲۵/...) بنویس؛ جایی که شواهد ماهیت دوگانه نشان می‌دهند (مثلاً هم فنی هم هنری)، توزیع را پخش‌تر و نزدیک‌به‌هم (مثلاً ۰.۲۸/۰.۲۴/۰.۲۲/...) بنویس.

۲. اگر دو رشتهٔ جدید به یک «خانوادهٔ حرفه‌ای» تعلق دارند (مثلاً دو رشتهٔ هنری یا دو رشتهٔ مهندسی دقیق)، شباهت نسبی طبیعی و قابل‌قبول است — **هدف صفرکردن شباهت نیست، هدف صداقت با شواهد است.** تلاش برای تمایز مصنوعیِ فراتر از شواهد واقعی، خودش تبدیل به منبع خطا می‌شود (این اتفاق افتاد و باید اصلاح می‌شد).

## مرحلهٔ ۴ — اعتبارسنجی (بعد از نوشتن هر رشته، نه در پایان همه)

### ۴.۱ چک ساختاری
هر ۲۵ ردیف دقیقاً ۵ مقدار، جمع هرکدام ≈ ۱.۰۰۰۱.

### ۴.۲ چک تصادف signature — **روی کل دیتابیس، نه فقط رشته‌های جدید**
```python
def sig(m): return tuple(row.index(max(row)) for row in m['strategy_weights'])
# این را روی مجموع ۱۶۰ رشتهٔ قبلی + ~۵۰ رشتهٔ جدید اجرا کن، نه فقط رشته‌های جدید جدا از هم
```
اگر دو رشته signature کاملاً یکسان (۲۵/۲۵) دارند، این حتماً باگ است و باید بازنویسی شود.

### ۴.۳ چک تمایز با نزدیک‌ترین هم‌خانواده
```python
agree = sum(1 for a, b in zip(sig(new_major), sig(existing_major)) if a == b)
```
- **۲۵/۲۵**: باگ قطعی، بازنویسی کن.
- **۲۰–۲۴/۲۵**: مشکوک — دوباره شواهد را بخوان، احتمالاً داری از الگوی عمومی به‌جای شواهد اختصاصی استفاده می‌کنی.
- **۱۳–۱۹/۲۵**: معمولاً قابل‌قبول برای رشته‌های واقعاً هم‌خانواده — اصلاح نکن مگر شاهد مشخصی خلافش را نشان دهد.

### ۴.۴ معیار پیوستهٔ همبستگی (Pearson) — فقط برای آگاهی، نه هدف‌گذاری سخت‌گیرانه
این معیار برای رشته‌های واقعاً نزدیک به‌هم (مثلاً دو رشتهٔ مهندسی دقیق) طبیعتاً بالا می‌ماند، حتی با شواهد کاملاً صادقانه. **تلاش برای رساندن این عدد به زیر یک آستانهٔ سخت‌گیرانه با قیمتِ دورشدن از شواهد واقعی، اشتباه است** — این تصمیم آگاهانه در این پروژه گرفته شد.

## مرحلهٔ ۵ — چیزی که در این پروژه کامل انجام نشد و باید برای رشته‌های جدید جبران شود

`value_weights` (۳۰ کلید، Q1A تا Q15B) هیچ‌وقت با همین سطح دقت میکرو-موتیوی بازبینی نشد — فقط `strategy_weights` این‌قدر دقیق بررسی شد. **برای ۵۰ رشتهٔ جدید، همین پروتکل (شواهد → نگاشت → وزن‌دهی → اعتبارسنجی) باید برای `value_weights` هم کامل اجرا شود**، با مراجعه به متن سؤالات `value_poles.json`.

## ترتیب کار پیشنهادی برای تیم

۱. برای هر رشته: شواهد را بخوان → هر ۲۵ سؤال راهبردی را جداگانه تصمیم بگیر (نه فقط ۵ سؤال «حیاتی» — این میان‌بر در این پروژه امتحان شد و ناکافی بود) → وزن‌دهی کن → چک ساختاری → چک تصادف روی کل دیتابیس.
