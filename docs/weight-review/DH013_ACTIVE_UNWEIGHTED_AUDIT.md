# DH-013 — ممیزی فعال‌های فاقد وزن واقعیِ احرازشده

تاریخ: ۲۰۲۶-۱۰-۲۵. **گزارش فقط‌خواندنی؛ هیچ وزن یا پرچم فعال‌سازی اصلاح نشده است.**
منبع ثابت ممیزی: HEAD فعلی `deploy/liara-commercial-sandbox` پس از Merge دستهٔ ۶، commit `d56c1c4e4cb6e23badad6c843d0d1560d7db2b4f`. این گزارش روی شاخهٔ اسنادیِ مبتنی بر main نوشته شده، اما دادهٔ main ورودی ممیزی نیست. همه داده‌ها با `git show <deploy-SHA>:<path>` خوانده شدند؛ موتور import/اجرا یا مولد وزن اجرا نشده است.

## ۱. نتیجهٔ اجرایی — سه مفهوم را یکی نگیریم
**۲۰۲ فعال = ۳۰ وزن تطبیق‌یافته با دسته‌های Mergeشدهٔ ۱–۶ + ۱۶۰ وزن تاریخیِ بازاحرازنشده + ۱۲ وزن نامزد قدیمیِ خارج از دسته‌ها.**
**وزن ناقص یا stub قطعی طبق آزمون‌های این ممیزی: ۰.** این نتیجه فقط فنی است و مجوز جملهٔ «همه ۲۰۲ وزن واقعی دارند» یا «باقی‌مانده = ۰» نیست.
**باقی‌مانده برای احراز وزن واقعی: ۱۷۲ مورد نامشخص** (۱۶۰ تاریخی + ۱۲ نامزد). این ۱۷۲ را «قطعاً بی‌وزن» نمی‌نامیم. تعداد واقعیِ فاقد وزن مبتنی بر شواهد از روی آرایه‌ها/اسناد موجود به‌تنهایی قابل تعیین قطعی نیست؛ تعداد احرازشدهٔ واقعی ۳۰ و تعداد احرازنشده ۱۷۲ است.
**در محدودهٔ فعال‌های جدید ۱۶۱–۲۳۰: ۳۰ از ۴۲ در دسته‌ها پوشش دارند و ۱۲ مورد هنوز پوشش اعمال‌شدهٔ BATCH ندارند.** نبود BATCH به‌تنهایی اثبات stub نیست.

## ۳. روش طبقه‌بندی و آزمون چهار بند ناظر
۱) برای همهٔ فعال‌ها وجود S، دقیقاً ۲۵ ردیف، عرض پنج، عدد متناهی در [۰،۱] و `abs(sum(row)-1) <= 0.001` کنترل شد. خطا: **۰**؛ بیشینهٔ خطای جمع حدود **۰٫۰۰۰۲** است.
۲) برای همهٔ فعال‌ها وجود V، تمام ۳۰ کلید لازم و عدد متناهی در [۰،۱] کنترل شد. کمبود کلید یا مقدار نامعتبر: **۰**.
۳) EQUAL در این گزارش یعنی هر پنج مقدار ردیف در فاصلهٔ `1e-9` از ۰٫۲ باشند. «اکثر» را فقط برای این ممیزی، بیش از نصف یعنی حداقل ۱۳ از ۲۵ تفسیر کردیم، نه گیت جدید. تعداد فعال با ۱۳+ یا ۲۵ ردیف EQUAL: **۰**؛ بیشینهٔ EQUAL فعال‌ها **۶** است. تمام ردیف‌های برابرِ ۳۰ رکورد BATCH با `EQUAL_NO_EVIDENCE` بستهٔ همان دسته، شماره‌به‌شماره تطبیق دارند؛ stub نیستند.
۴) برای «بدون BATCH و همسان با stub اولیه»، هر دو شرط لازم‌اند. دوازده مورد جدید بدون BATCH هستند، ولی وزن فعلی‌شان با stub اولیهٔ خالی `[]/{}` برابر نیست و با candidateهای F2/F3/F4 تطبیق دقیق دارد؛ بنابراین بند ۴ برایشان **اثبات نشده**. در پروتکل، یک fingerprint عددی سراسری برای stub تعریف نشده؛ نبود سند BATCH یا کم بودن EQUAL به‌تنهایی تشخیص stub/واقعی نمی‌دهد.
تعریف برچسب‌ها: «واقعی» در جدول = مستندات نگاشت S/V و اعمال در BATCH Mergeشده + تطبیق دقیق عدد جاری با patch؛ «ناقص» = خرابی ساختار/کلید؛ «stub» = پیش‌فرض/جای‌نگهدار اثبات‌شده؛ «نامشخص» = سالم از نظر عددی اما احراز روش کنونی کامل نیست. هیچ برچسبی به معنای کالیبراسیون روان‌سنجی نیست.

- ۱۲ نامزد جدید در نسخه‌های catalog-only واقعاً `strategy_weights=[]` و `value_weights={}` داشتند: `70de2dc` برای ۲۰۳/۲۰۴، `a36bcef` برای ۲۰۵/۲۰۸/۲۰۹–۲۱۴، `5f72c0b` برای ۲۱۹/۲۲۰. اکنون هیچ‌یک با آن وضعیت برابر نیست.

- [پروتکل اولیه](https://github.com/arad2000/dark-horse-v2-/blob/a1cdab9cd875bf9e9e01c19debf1e1237f58302b/docs/protocols/DH013_MAJOR_WEIGHTING_PROTOCOL.md) روش استفاده‌شده برای ۱۶۰ را شرح می‌دهد، اما مرحلهٔ ۵ تصریح می‌کند V همان سطح بازبینی S را نداشته است؛ [سند نهایی BATCH1](https://github.com/arad2000/dark-horse-v2-/blob/d56c1c4e4cb6e23badad6c843d0d1560d7db2b4f/docs/weight-review/DH013_BATCH1_161_165_FINAL_PROPOSAL.md) نیز صریحاً سلامت علمی همهٔ ۱۶۰ را مفروض نمی‌داند. پس در این ممیزی کوتاه، ۱۶۰ را بدون بررسی ردیف‌به‌ردیف «تأییدشده» ارتقا نمی‌دهیم.

## ۹. بازتولید فقط‌خواندنی
این نمونه هیچ فایل runtime را نمی‌نویسد؛ برای اجرا به تاریخچهٔ commitهای منبع نیاز است. خروجی آن counts، تطبیق بسته‌ها و صف ۱۲ مورد را نشان می‌دهد. کنترل تاریخچهٔ stub و تطبیق F2/F3/F4 نیز در این ممیزی جدا انجام شده است.
```python
import json, subprocess
R = "d56c1c4e4cb6e23badad6c843d0d1560d7db2b4f"
def read(path):
    return json.loads(subprocess.check_output(["git", "show", R+":"+path]))
majors = read("majors_database_v2.json")
active = [m for m in majors if m["motive_driven"]]
keys = {f"Q{i}{a}" for i in range(1,16) for a in "AB"}
patches = {}
files = ["DH013_BATCH1_161_165_FINAL_PROPOSAL.json",
         "DH013_BATCH2_166_170.json", "DH013_BATCH3_171_175.json",
         "DH013_BATCH4_176_177_178_180_181.json",
         "DH013_BATCH5_182_183_184_185_186.json",
         "DH013_BATCH6_187_189_199_201_202.json"]
for n, file in enumerate(files,1):
    p = read("docs/weight-review/"+file)
    if n == 1:
        for m in p["major_patches"]:
            patches[m["id"]] = (m["strategy_weights"],m["value_weights"])
    elif n == 2:
        for m in p["majors"]:
            w = m["weight_patch"]
            patches[m["id"]] = (w["strategy_weights"],w["value_weights"])
    else:
        for m in p["proposals"]:
            if m["write_weights"]:
                patches[m["id"]] = ([r["weights"] for r in m["strategies"]],
                                     m["value_weights"])
for m in active:
    s,v = m.get("strategy_weights"), m.get("value_weights")
    assert isinstance(s,list) and len(s)==25
    assert all(len(row)==5 and abs(sum(row)-1)<=.001 for row in s)
    assert isinstance(v,dict) and keys <= v.keys()
    if m["id"] in patches:
        assert (s,v) == patches[m["id"]]
assert len(active)==202 and len(patches)==30
legacy = [m["id"] for m in active if m["id"]<=160]
new_pending = [m["id"] for m in active if m["id"]>160 and m["id"] not in patches]
print("active",len(active),"batch_verified",len(patches),
      "legacy_not_revalidated",len(legacy),"new_pending",len(new_pending))
print("new_pending_ids",new_pending)
print("all_unconfirmed_ids",sorted(legacy+new_pending))
```
